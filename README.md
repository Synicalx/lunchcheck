# LunchCheck

LunchCheck is a premium, dark-themed personal finance and habit-tracking Flutter application designed to help users track their daily lunch expenses, encourage packing home-prepared meals, and stay within their budget.

---

## Key Features

*   **Daily Log Tracking**: Log daily lunch details including:
    *   Whether you brought your lunch (automatically tracks as $0.00 actual spend).
    *   Whether you bought your lunch (log actual spend against your daily target budget).
*   **Weekly Analytics & Metrics**: View weekly summaries of:
    *   **Total Spent**: Total spent on bought lunches.
    *   **Total Saved**: Savings generated by bringing lunches vs. eating out.
    *   **Overspent**: Visual warnings and metrics when spending exceeds the daily target.
*   **Intelligent Local Notifications**: Setup custom notification schedules (select specific active days and custom reminder times) to prompt you to log daily entries.
*   **Data Portability**: Backup and restore your history at any time with JSON-based import and export features.
*   **Offline First**: Built with Hive local storage for fast, reliable, and completely offline data management.

---

## Technical Stack

*   **Framework**: [Flutter](https://flutter.dev/) (SDK target version `^3.7.2` / Dart `^3.7.2`)
*   **State Management**: [Provider](https://pub.dev/packages/provider)
*   **Storage**: [Hive](https://pub.dev/packages/hive) & [Hive Flutter](https://pub.dev/packages/hive_flutter)

*   **Date & Time**: [Timezone](https://pub.dev/packages/timezone) & [Flutter Timezone](https://pub.dev/packages/flutter_timezone)

## Getting Started

### Prerequisites

To run this project locally, ensure you have the following installed:
*   [Flutter SDK](https://docs.flutter.dev/get-started/install) (matching version requirements)
*   [Java Development Kit (JDK)](https://adoptium.net/) (Java 17 is recommended for building Android)
*   [Android Studio](https://developer.android.com/studio) (for Android SDK tools and emulator) or [Xcode](https://developer.apple.com/xcode/) (for iOS simulator, macOS only)

### Installation & Setup

1.  **Clone the repository**:
    ```bash
    git clone <your-repository-url>
    cd lunchcheck
    ```

2.  **Fetch Flutter packages**:
    ```bash
    flutter pub get
    ```

3.  **Check for issues**:
    Ensure your Flutter development environment is properly configured:
    ```bash
    flutter doctor
    ```

## Running the Application

To run the application in debug mode on a connected device or emulator:

1.  List available devices:
    ```bash
    flutter devices
    ```
2.  Start the app:
    ```bash
    flutter run
    ```
    *(If multiple devices are connected, specify target device via `flutter run -d <device-id>`)*

## Manual Building

You can build release versions of the application locally:

### Android (APK)

To build a release APK signed with your debug signature (configured in Gradle):
```bash
flutter build apk --release
```

*   **Output Path**: `build/app/outputs/flutter-apk/app-release.apk`
*   **Custom Versioning**:
    You can override version settings during the build command:
    ```bash
    flutter build apk --release --build-name=1.0.0 --build-number=1
    ```

### iOS

To build an iOS release bundle (requires macOS and Xcode):
```bash
flutter build ios --release --no-codesign
```

## CI/CD Pipeline (GitHub Actions)

We have configured a manual GitHub Actions pipeline to compile the Android APK in the cloud. This helps preserve your local machine's computing power and GitHub's free-tier usage by only building when triggered.

### How to use:
1.  Navigate to your repository page on GitHub.
2.  Click the **Actions** tab.
3.  Select **Build Android APK** from the workflows list on the left side.
4.  Click the **Run workflow** dropdown on the right side.
5.  *(Optional)* Enter a custom **Build name** (e.g. `1.1.0`) and **Build number** (e.g. `3`).
6.  Click the green **Run workflow** button.
7.  Once the workflow completes successfully, download the installer APK from the **Artifacts** section at the bottom of the run page.
